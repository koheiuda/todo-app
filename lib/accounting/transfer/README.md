# 外注費の一括振込（総合振込・全銀フォーマット）

月次画面の外注費をまとめて、GMOあおぞらネット銀行にアップロードできる
**総合振込ファイル（全銀協フォーマット・Shift_JIS・120バイト固定長）** を書き出す。

## なぜAPIではなくファイルなのか

GMOあおぞらネット銀行の振込APIは、利用申込 → 事前ヒアリング → 接続審査 → API利用契約と進み、
**本番環境で接続できるまで概ね2ヶ月かかる**。総合振込ファイルなら契約を待たずに今月から使える。
そのうえ、出金の実行判断は銀行側の画面（承認operation）に残るので、
アプリ側の不具合がそのまま誤送金になることがない。

APIへ移行する場合も、振込先口座マスタ（`payee_accounts`）と検証ロジックはそのまま再利用できる。

## 使うまでの手順

1. マイグレーションを流す（非破壊。既存データは触らない）

   ```bash
   npx tsx --env-file=.env.local scripts/migrate-add-payee-accounts.ts          # dry-run
   npx tsx --env-file=.env.local scripts/migrate-add-payee-accounts.ts --apply
   ```

2. `/accounting/company` の「総合振込（振込元）」に自社の情報を入れる
   - 委託者コード（10桁）は **銀行から払い出される**。未取得なら銀行に発行を依頼する
   - 金融機関コード・支店コード・口座番号・委託者名カナ

3. `/accounting/payees` に外注先の口座を登録する
   - 外注先名は外注費の名称と一致させると自動で紐付く
   - 受取人名は**通帳どおりのカナ**。入力欄の下に全銀表記と文字数が出る

4. 月次画面（`/accounting/months/YYYY-MM`）の外注費セクションで「一括振込」

5. 出来たファイルを GMOあおぞらネット銀行の総合振込にアップロードし、**銀行側で承認する**

## 安全側に倒している点

- **このアプリは出金しない。** ファイルを作るだけで、実行は銀行の承認操作による
- 口座が未登録・無効・桁数不正の行は、理由を出したうえで**ファイルに含めない**（黙って落とさない）
- 金額0以下の行は対象外（金額未確定の行を誤って送らないため）
- 書き出した内容は `transfer_batches` に丸ごと残り、同じ月を再度開くと警告が出る（二重振込の検知）
- 受取人名は保存時に半角カナへ正規化し、全銀に通らない文字があれば保存前に弾く

## 構成

| ファイル | 役割 |
| --- | --- |
| `kana.ts` | 全角カナ・ひらがな・全角英数 → 全銀の半角文字への正規化、法人格の略語化 |
| `zengin.ts` | 全銀フォーマットのレコード組み立て、Shift_JISエンコード、振込先の検証 |
| `build.ts` | 外注費と口座マスタの突き合わせ、振込可否の判定 |
| `queries.ts` | DBからの読み出し |

`kana.ts` / `zengin.ts` / `build.ts` は外部依存のない純粋なロジックで、テストがある。

```bash
npm run test:transfer
```

## 全銀フォーマットの要点（実装の根拠）

- 1レコード120バイト固定長。ヘッダ(1) → データ(2)×N → トレーラ(8) → エンド(9)
- 受取人名は30桁。**濁点・半濁点は独立した1文字**として桁を食う（ｶﾞ は2文字）
- 拗音・促音の小書きは使えないため大文字へ寄せる（ｷｬ→ｷﾔ、ｯ→ﾂ）
- 使えるのは半角英大文字・半角数字・半角カナと一部記号（スペース . - ( ) / ,）
